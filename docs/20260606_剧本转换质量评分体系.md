# 剧本转换质量评分体系优化规划

文档版本：v2.0（规划稿）  
原始版本：v1.0，2026-06-06  
更新时间：2026-06-07 11:08  
适用项目：Novel2Script，AI 小说转剧本工具  
适用场景：评价“小说文本 -> YAML 结构化剧本”的生成质量，并为自动修复和人工打磨提供依据。

## 1. 修订结论

原 v1.0 体系具备工程可落地性，已经覆盖 Schema、引用一致性、章节和事件覆盖、人物一致性、可演性、忠实度及自动修复，可作为第一版质量检查方案。

但原方案不宜直接宣称为“客观剧本质量分”，主要原因如下：

- 将确定性指标和 AI 主观评价合并成单一总分，会产生不必要的精确感。
- Schema 合规既是硬门槛，又在“结构完整度”中重复计分。
- 章节或事件 ID 被引用，不代表对应内容真正进入剧本。
- 所有章节和事件等权，不符合改编中保留、合并、压缩和省略的实际需要。
- 缺少因果连贯、人物弧光、对白人物声纹、节奏和主题表达等专业维度。
- 忠实度判断缺少原文证据，AI 评分难以复核。
- `85/70` 等阈值尚未经过样本和人工评分标定。

因此，v2.0 采用三层评价模型：

```text
第一层：硬性门槛 Gate
  -> 第二层：确定性质量指标 Metrics
  -> 第三层：AI 专业评审 Rubric
  -> 决策与自动修复
```

## 2. 设计原则

### 2.1 合规与质量分离

YAML 是否可解析、Schema 是否通过、引用是否有效属于“能否使用”的门槛，不属于艺术或改编质量，不进入 AI 总分。

### 2.2 客观指标与主观判断分离

覆盖率、引用一致性、场景元素数量等由程序计算；忠实度、因果连贯、戏剧性、对白质量等由 AI 按量表评价。前端分别展示，不将两者混成一个无法解释的总分。

### 2.3 每项判断可追溯

AI 指出问题时必须提供：

- 对应场景 ID。
- 对应原文章节或事件 ID。
- 原文证据摘要或短引用。
- 判断理由。
- 修改建议。
- 置信度。

### 2.4 评分服务于修改

评分不是最终目的。每个未达标项必须能映射到 Reader、Planner、Writer 或 Validator 的具体修复动作。

## 3. 第一层：硬性门槛

硬性门槛不计分。任一关键项失败，项目不得标记为 `completed`。

### 3.1 YAML 与 Schema

- YAML 文本可解析，顶层为对象。
- 符合 `backend/schema.json`。
- 输入和输出章节数量均不少于 3 章。
- 每个场景至少包含 3 个剧本元素。
- ID 格式、枚举值和数组唯一性符合 Schema。

### 3.2 引用完整性

- 地点、章节、事件、人物 ID 均能解析到已有对象。
- 对白人物必须存在于人物表，并属于当前场景人物。
- 场景引用的章节和事件必须存在。
- 事件来源章节及事件人物必须存在。

### 3.3 最低可用性

- 至少存在一个主要人物。
- 至少存在一个关键事件。
- 每个场景包含动作或对白等可执行元素。
- 最终 YAML 能被重新读取并得到等价结构。

### 3.4 门槛结果

```json
{
  "gate": {
    "passed": true,
    "schema_valid": true,
    "references_valid": true,
    "minimum_usability": true,
    "errors": []
  }
}
```

Schema 或引用错误进入 Writer 局部修复，最多两轮；两轮后仍失败，项目状态为 `failed`。

## 4. 第二层：确定性质量指标

确定性指标只展示测量结果和风险状态，不直接充当剧本艺术质量总分。

| 指标 | 计算方式 | 用途 |
|---|---|---|
| 章节映射率 | 被场景引用章节数 / 总章节数 | 检查是否存在整章遗漏 |
| 事件引用率 | 被剧本元素引用事件数 / 总事件数 | 检查 Planner 事件是否进入剧本 |
| 重要事件覆盖率 | 已覆盖事件重要度之和 / 全部事件重要度之和 | 优先保证主线而非机械全覆盖 |
| 引用一致性 | 有效引用数 / 全部受检引用数 | 发现悬空 ID |
| 场景完整率 | 至少含 3 个元素且有目的、冲突的场景数 / 总场景数 | 发现不完整场景 |
| 对白占比 | dialogue 元素数 / 全部剧本元素数 | 作为文体观察值 |
| 动作覆盖率 | 含 action 元素场景数 / 总场景数 | 发现纯摘要或纯对白场景 |
| 平均场景长度 | 场景元素总数 / 场景数 | 识别过短或异常膨胀 |

### 4.1 重要度加权覆盖

Planner 为事件增加重要度和改编策略：

```yaml
events:
  - id: event_001
    importance: 5
    adaptation_action: retain
  - id: event_002
    importance: 2
    adaptation_action: merge
  - id: event_003
    importance: 1
    adaptation_action: omit
    omission_reason: "与主线重复，压缩篇幅"
```

`adaptation_action` 取值：

- `retain`：保留为独立事件。
- `merge`：与其他事件合并。
- `compress`：压缩为较短场景或元素。
- `omit`：有理由地省略。

事件覆盖不能只检查 `event_id` 是否出现，还应验证场景内容是否语义实现该事件。ID 覆盖和语义覆盖分别记录。

### 4.2 指标使用限制

- 对白占比不设置跨题材统一合格区间，只标记极端值供 AI 复核。
- 章节映射率不能强制每章等量改编。
- 指标异常只能触发检查，不能单独证明剧本质量差。

## 5. 第三层：AI 专业评审

AI 评审总分为 100 分，仅代表当前评价模型按既定量表给出的“改编初稿可用性评分”，不代表行业通用或客观艺术评分。

| 维度 | 权重 | 核心问题 |
|---|---:|---|
| 改编忠实度 | 25 | 是否保留核心事实、人物关系、主线冲突和主题意图 |
| 因果连贯性 | 20 | 场景和事件之间是否存在清晰、完整的因果链 |
| 场景戏剧性与可演性 | 20 | 场景是否有目标、阻力、转折及可拍摄行动 |
| 人物一致性与弧光 | 15 | 人物身份、动机、行为变化是否合理且连续 |
| 对白自然度与人物声纹 | 15 | 对白是否自然、推进剧情且能区分人物 |
| 节奏与转场 | 5 | 场景长度、信息密度和转场是否合理 |

计算公式：

```text
ai_score =
  fidelity * 0.25
+ causal_coherence * 0.20
+ scene_dramaturgy * 0.20
+ character_arc * 0.15
+ dialogue_voice * 0.15
+ pacing_transition * 0.05
```

### 5.1 改编忠实度

检查：

- 是否新增原文不存在的关键事实。
- 是否改变人物身份、关系、动机或结局。
- 是否遗漏主线冲突。
- 心理描写转化为动作或对白后，原意是否保留。
- 合并和省略是否有明确、合理的改编说明。

AI 应先将判断拆成原子事实，再逐项对照 Reader 事实和原文证据，降低笼统评分造成的误判。

### 5.2 因果连贯性

检查：

- 每个关键场景是否由前序事件或人物目标触发。
- 人物决策是否有可见动机。
- 转折是否有铺垫。
- 事件结果是否推动后续情节。
- 删除或合并内容后是否破坏因果链。

Planner 应提供事件关系：

```yaml
causal_links:
  - from_event: event_001
    to_event: event_003
    relation: causes
```

### 5.3 场景戏剧性与可演性

检查：

- 场景目标、阻力、冲突和结果是否明确。
- 动作是否可观察、可表演、可拍摄。
- 场景是否推动情节或人物变化。
- 是否将小说摘要直接包装成旁白。
- 是否存在重复场景或无功能场景。

不以固定对白比例代替可演性判断。

### 5.4 人物一致性与弧光

检查：

- 人物身份、关系、知识边界是否前后一致。
- 行为是否符合当前目标和处境。
- 重大态度变化是否有事件支撑。
- 主要人物是否经历可识别的状态变化。
- 配角是否具有明确的场景功能。

Planner 应为主要人物保留初始状态、目标、障碍、关键转变和最终状态，便于 Validator 对比。

### 5.5 对白自然度与人物声纹

检查：

- 对白是否服务于行动、冲突或信息揭示。
- 不同人物在用词、句长、态度和表达策略上是否可区分。
- 是否存在说明性对白、模板句和重复表达。
- 潜台词是否与人物关系和场景目标一致。
- 对白人物是否拥有当前信息，避免越界知情。

### 5.6 节奏与转场

检查：

- 重要事件是否获得足够篇幅。
- 次要内容是否过度展开。
- 连续场景是否重复同一信息。
- 时间、空间和情绪转场是否可理解。

## 6. AI 评分量表

各维度使用统一的五档锚点，再映射为 0-100 分，减少模型随意给分。

| 档位 | 分数参考 | 定义 |
|---|---:|---|
| 5 | 90-100 | 证据充分，几乎无实质问题，可直接进入人工润色 |
| 4 | 75-89 | 整体可靠，存在少量局部问题 |
| 3 | 60-74 | 主体可辨认，但有明显遗漏、薄弱或不自然之处 |
| 2 | 40-59 | 多处关键问题，需重写部分场景 |
| 1 | 0-39 | 严重偏离原文或不具备剧本初稿可用性 |

每项输出必须包含：

```json
{
  "dimension": "causal_coherence",
  "score": 72,
  "confidence": 0.81,
  "evidence": [
    {
      "scene_id": "scene_003",
      "source_chapters": ["chapter_002"],
      "source_events": ["event_004"],
      "reason": "人物决定离开缺少前序触发事件"
    }
  ],
  "suggestion": "在 scene_002 增加人物获知真相后的行动或对白铺垫"
}
```

置信度低于建议阈值时，前端显示“需要人工复核”，不自动据此大范围重写。

## 7. 综合决策

系统同时返回三类结果：

```text
合规状态：通过 / 失败
确定性指标：原始比例和风险提示
AI 初稿评分：0-100、分项评分、证据和置信度
```

建议初始决策规则：

| 条件 | 项目状态 | 处理方式 |
|---|---|---|
| 硬性门槛失败 | `failed` 或修复中 | 局部修复，最多两轮 |
| 硬性门槛通过，存在 AI 高严重度问题 | `completed_with_warnings` | 局部修复或人工确认 |
| 硬性门槛通过，AI 评分偏低 | `completed_with_warnings` | 展示具体证据，不直接判废 |
| 硬性门槛通过，无高严重度问题 | `completed` | 保存并展示 |

在完成标定前，不使用固定 `85/70` 阈值对作品作“高质量/不通过”的绝对判断。阈值只作为内部实验参数。

## 8. 自动修复路由

| 问题 | 责任 Agent | 建议动作 |
|---|---|---|
| 章节边界或事实错误 | Reader | 重读相关章节 |
| 关键事件、人物关系或因果链缺失 | Planner | 局部补充事实层和场景规划 |
| YAML、字段或引用错误 | Writer | 结构化局部修复 |
| 事件未被语义实现 | Writer | 重写对应场景元素 |
| 单场目标、冲突或行动薄弱 | Writer | 局部场景重写 |
| 对白模板化或人物声音趋同 | Writer | 仅重写相关对白 |
| 原文幻觉或人物关系改变 | Planner + Writer | 纠正事实层后重写问题场景 |
| AI 判断证据不足 | Validator | 补充证据或标记人工复核 |

自动修复约束：

- 最多两轮。
- 优先局部修复，不重跑无关 Agent。
- 保存修复前后剧本、指标、AI 评分和问题证据。
- 每轮必须记录分数变化，避免“修复后反而退化”。
- 新版本门槛或关键指标变差时，回退到上一版本。

## 10. 前端展示规划

前端不再只展示一个“AI 质量评分”，应分为：

1. **结构合规**：Schema、引用、最低可用性。
2. **数据指标**：覆盖、完整、对白和动作比例。
3. **AI 专业评审**：六个维度、置信度和严重度。
4. **问题证据**：场景、来源章节、事件、理由和建议。
5. **修复记录**：修复轮次、前后指标变化和改动范围。

建议使用指标卡和问题列表。雷达图只用于辅助比较，不替代具体证据。

## 11. 标定与验收规划

在将 AI 分数用于正式评审前，应进行小规模标定：

- 准备 20-30 个不同题材、长度和质量等级的转换样本。
- 邀请 2-3 名具有剧本阅读或创作经验的评价者独立评分。
- 使用统一量表，记录评价者之间的一致性。
- 比较 AI 分数与人工评分的相关性。
- 分析高严重度问题的准确率、误报率和漏报率。
- 根据结果调整权重、锚点、阈值和提示词。
- 固定模型、温度、评分提示词和评分版本，保证复测可比。

建议验收指标：

- 硬性校验结果可重复且测试覆盖完整。
- 同一固定输入的 AI 分项评分波动处于可接受范围。
- AI 问题均能定位到具体场景并提供来源证据。
- 高严重度问题经过人工抽查具有可接受准确率。
- 自动修复后门槛不退化，目标问题得到改善。

## 12. 分阶段实施计划

### 第一阶段：重构输出结构

- 保留现有六项确定性指标。
- 删除结构合规的重复计分。
- 将 `quality_metrics.json` 拆分为 `gate`、`deterministic_metrics`、`ai_review` 和 `repair`。
- 前端将“总分”改为“AI 初稿评分”，并独立显示合规状态。

### 第二阶段：增强 Planner 事实层

- 为事件增加 `importance` 和 `adaptation_action`。
- 增加事件因果关系。
- 增加主要人物弧光字段。
- 支持保留、合并、压缩和省略的改编说明。

### 第三阶段：增强 Validator

- 按六维量表分别评分。
- 强制输出场景、章节、事件证据和置信度。
- 增加语义事件覆盖和原子事实忠实度检查。
- 按问题类型生成可执行的 `rewrite_scope`。

### 第四阶段：标定与评测

- 建立固定评测集和人工评分表。
- 输出 AI 与人工评分对比报告。
- 根据数据确定正式阈值。
- 记录评分体系版本，保证历史项目可追溯。

## 13. 当前限制

- AI 评分受模型、提示词和上下文截断影响。
- 文学改编不存在唯一正确答案，忠实度和戏剧性之间存在权衡。
- 短篇样本的权重和阈值不能直接推广到长篇、类型剧或实验性作品。
- 自动指标适合发现结构和覆盖风险，不能替代专业编剧的整体判断。
- 在完成人工标定前，本体系应被描述为“剧本初稿质量诊断与修复系统”，不应宣传为行业标准评分。

## 15. 总结

v2.0 的核心变化不是增加更多分数，而是提高评价结论的可信度和可执行性：

- 用硬门槛保证 YAML 可用。
- 用确定性指标暴露结构和覆盖风险。
- 用带证据和置信度的 AI 量表评价改编质量。
- 用问题路由驱动局部修复。
- 用人工标定确定最终权重和阈值。

该结构更适合评审展示，也能避免把模型主观判断包装成缺乏依据的客观分数。
