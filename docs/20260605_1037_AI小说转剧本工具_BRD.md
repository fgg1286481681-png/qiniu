# AI 小说转剧本工具 BRD

文档版本：v1.0  
创建时间：2026-06-05 10:37  
项目代号：Novel2Script  
适用议题：题目三，AI 小说转剧本工具

## 1. 背景

小说 IP 改编为影视、短剧、广播剧和互动内容时，通常需要经历拆章、提炼人物、梳理情节、拆分场景、改写对白、整理动作说明、反复校对结构等步骤。这个过程高度依赖人工经验，前期剧本初稿生产成本高、周期长，且产出格式经常不统一，后续难以被编辑器、制作流程或二次 AI 工具稳定消费。

本实训题目要求将 3 个章节以上小说文本自动转换为结构化剧本 YAML，并额外定义 YAML Schema。相比实时语音类题目，本项目更适合在 3 天交付期内做出稳定、可演示、可验证的完整闭环。

## 2. 外部调研摘要

1. ScreenJSON 将剧本视为结构化、层级化、带类型的文档，强调角色、场景、元素具备稳定标识，方便查询、转换、渲染和输入给 LLM。参考：https://screenjson.com/
2. Final Draft 的核心价值不只是写作，还包括 Beat Board、Outline Editor、自动格式化、修订评论、协作和生产拆解，说明专业剧本工具重视“结构规划 + 可编辑工作流”。参考：https://www.finaldraft.com/products/features/
3. Sudowrite 面向小说作者，提供 Write、Rewrite、Brainstorm、Scenes、Draft 等 AI 写作能力，说明创作者愿意为“在创作流程中可控地使用 AI”付费。参考：https://docs.sudowrite.com/getting-started/dQph1snuwbfMWG9wRjsNug/features/dq7YUMNy5ZMvKUJiRAisyT
4. 2025 年论文 R2: A LLM Based Novel-to-Screenplay Generation Framework with Causal Plot Graphs 指出小说转剧本的关键挑战包括长文本幻觉、情节抽取不一致、因果情节线保持，并提出 Reader/Rewriter 分阶段方案。参考：https://arxiv.org/abs/2503.15655
5. NovelVids 的小说转短剧流程使用实体抽取、资产管理、分镜生成、视频合成四阶段流水线，说明“实体一致性”和“结构化中间产物”是后续视频化生产的关键。参考：https://novelvids.com/

## 3. 商业目标

本项目的商业目标不是替代专业编剧，而是提供“小说到剧本初稿”的 AI 生产力工具，降低改编前期成本，并产出可被人类编辑继续打磨的结构化底稿。

核心目标：

- 将小说改编初稿产出时间从数小时或数天压缩到分钟级。
- 让输出结果具备标准化 YAML 结构，便于校验、编辑、导出和二次处理。
- 通过人物、场景、事件、对白、动作、旁白等结构拆解，体现对原文的理解能力。
- 在实训评审中展示完整产品闭环、工程化校验能力和 AI 编排能力。

## 4. 用户与客户

目标用户：

- 小说作者：希望快速获得可打磨的剧本初稿。
- 短剧编导：希望从网文、短篇小说中快速拆出场景和对白。
- 内容工作室：希望批量评估 IP 改编潜力。
- 实训评审：关注选题符合度、完整度、技术实现、文档规范和演示效果。

潜在付费客户：

- 小型 MCN 或短剧团队。
- 网文平台 IP 开发团队。
- 独立编剧和创作者。
- AIGC 内容生产工具平台。

## 5. 核心价值主张

Novel2Script 提供从小说文本到结构化剧本 YAML 的一站式转换能力。

用户上传或粘贴至少 3 个章节的小说文本后，系统自动完成章节识别、人物抽取、场景拆分、事件梳理、对白改写、动作/旁白分离、YAML 生成和 Schema 校验。用户可以在页面中预览、编辑、重新生成局部内容，并导出 YAML 文件。

## 6. 成本与收益判断

开发成本：

- 前端：文本输入、章节列表、生成进度、YAML 预览、校验结果、导出功能。
- 后端：章节分块、Prompt 编排、模型调用、YAML 解析、Schema 校验、错误修复。
- 文档：YAML Schema 设计说明、运行说明、README、Demo 视频。

成本可控原因：

- 主要处理文本，不依赖实时音频、视频或低延迟流式链路。
- 可使用通用 LLM 生成结构化内容，通过 Schema 校验提升稳定性。
- MVP 不必接入复杂专业剧本格式，只需满足 YAML 和可编辑要求。

预期收益：

- 评审可直接验证输入输出，展示路径清晰。
- 文档与 Schema 能体现工程规范。
- 相比普通聊天式 AI 写作工具，结构化产物更有技术辨识度。

## 7. 项目范围

MVP 必做：

- 支持输入 3 个章节以上小说文本。
- 自动识别章节边界。
- 抽取人物、地点、关键事件。
- 生成 YAML 格式剧本。
- 提供 YAML Schema 文档。
- 支持 YAML Schema 校验。
- 支持生成摘要和改编说明。
- 支持导出 YAML。

增强功能：

- 局部重写某一场戏。
- 原文与剧本场景映射。
- 人物关系图。
- 多剧本类型模板：短剧、影视、广播剧。
- 质量评分：结构完整度、对白占比、角色一致性、场景覆盖度。

暂不做：

- 专业 Final Draft FDX 导入导出。
- 视频生成。
- 多人协作。
- 版权检测和法律审查。
- 商业支付系统。

## 8. 成功指标

评审阶段成功指标：

- 可以用 3 个章节以上样例文本完整生成 YAML 剧本。
- 生成结果通过 YAML 解析和 Schema 校验。
- 输出包含人物表、场景列表、对白、动作、旁白、改编说明。
- Demo 视频中流程不依赖人工补救。
- README 和 Schema 文档清晰可读。

产品指标：

- 章节识别成功率大于 90%。
- YAML 解析成功率大于 95%。
- 单次生成失败后自动修复成功率大于 80%。
- 3 章文本端到端生成时间小于 3 分钟。
- 用户可编辑并导出最终 YAML。

## 9. 风险

- 长文本超出模型上下文：使用章节级分块、摘要压缩和最终合并。
- 模型生成 YAML 不合法：使用 JSON/YAML Schema 校验和自动修复。
- 人物名称不一致：建立角色 ID 和别名表。
- 情节因果断裂：先生成章节事件图，再生成场景大纲，最后生成剧本。
- 原文版权风险：Demo 使用自写样例或公版文本片段，避免上传侵权材料。

## 10. 推荐实施策略

采用“Reader -> Planner -> Rewriter -> Validator”的四阶段架构：

1. Reader：解析章节，抽取人物、地点、事件和冲突。
2. Planner：将事件重组为剧本场景大纲。
3. Rewriter：把场景大纲改写为 YAML 剧本。
4. Validator：执行 YAML 解析、Schema 校验和自动修复。

该策略兼顾实现难度和技术含金量，适合 2026-06-05 至 2026-06-07 的短周期交付。
