## 1. 产品概述

Novel2Script 是一款 AI 小说转剧本工具。用户输入至少 3 个章节的小说文本，系统自动分析章节、人物、地点和关键事件，并生成符合 YAML Schema 的结构化剧本初稿。用户可查看人物表、场景列表、剧本 YAML、校验结果和改编总结，并导出 YAML 文件。

## 2. 产品目标

P0 目标：

- 满足实训题目要求：3 个章节以上小说文本自动转换为结构化 YAML 剧本。
- 提供 YAML Schema 设计文档。
- 完成从输入、生成、校验、编辑到导出的完整闭环。

P1 目标：

- 提供局部重写能力。
- 提供原文与剧本场景映射。
- 提供质量评分和改编摘要。

## 3. 用户流程

主流程：

1. 用户进入首页。
2. 用户粘贴小说文本或上传 `.txt` 文件。
3. 系统识别章节数量。
4. 若少于 3 章，提示用户补充文本。
5. 用户点击“生成剧本”。
6. 系统展示生成进度：章节解析、信息抽取、场景规划、剧本生成、Schema 校验。
7. 系统展示结果：人物表、场景表、YAML 剧本、校验报告、改编总结。
8. 用户可编辑 YAML 或重新生成某一场戏。
9. 用户导出 YAML 文件。

异常流程：

- 章节不足：禁止生成，提示至少需要 3 个章节。
- 模型返回格式错误：自动执行一次修复；失败后展示错误原因和原始输出。
- Schema 校验失败：标出字段路径和错误原因。
- 网络或模型调用失败：保留用户输入，允许重试。

## 4. 信息架构

页面结构：

- 顶部栏：产品名称、当前项目、导出按钮。
- 左侧输入区：文本输入、文件上传、样例载入、章节识别结果。
- 中间工作区：生成进度、人物表、场景表、改编摘要。
- 右侧输出区：YAML 编辑器、Schema 校验报告、复制按钮。

核心数据对象：

- NovelProject：项目。
- Chapter：章节。
- Character：人物。
- Location：地点。
- Event：关键事件。
- Scene：剧本场景。
- ScriptDocument：完整 YAML 剧本。
- ValidationResult：校验结果。

## 5. 功能需求

### 5.1 小说输入

优先级：P0

功能说明：

- 支持粘贴小说全文。
- 支持上传 `.txt` 文件。
- 支持载入内置样例。
- 自动统计字数和章节数。

验收标准：

- 输入为空时不能生成。
- 少于 3 章时不能生成。
- 支持常见章节标题：第1章、第一章、Chapter 1、章节一。
- 文件编码优先支持 UTF-8。

### 5.2 章节解析

优先级：P0

功能说明：

- 根据标题规则拆分章节。
- 若无法识别标题，允许按段落长度进行辅助拆分，但必须提示用户。
- 输出章节列表和每章字数。

验收标准：

- 3 章样例文本可以正确识别。
- 每个章节具备 `chapter_id`、`title`、`order`、`text`。

### 5.3 信息抽取

优先级：P0

功能说明：

- 从每章中抽取人物、地点、关键事件、冲突、情绪变化。
- 对人物设置稳定 ID，记录别名。
- 对事件记录来源章节。

验收标准：

- 至少输出 3 个关键事件。
- 每个主要人物包含姓名、简介、人物目标或关系说明。
- 同名或别名人物应尽量合并。

### 5.4 场景规划

优先级：P0

功能说明：

- 将章节事件转化为剧本场景。
- 每个场景包含地点、时间、出场人物、场景目的、冲突、剧情摘要。
- 支持短剧风格，强调冲突和钩子。

验收标准：

- 每章至少生成 1 个场景。
- 场景顺序符合原文主线。
- 每个场景都有明确戏剧功能。

### 5.5 剧本 YAML 生成

优先级：P0

功能说明：

- 根据场景规划生成结构化 YAML。
- YAML 包含元信息、人物、地点、场景、对白、动作、旁白和改编说明。
- 对白、动作、旁白使用不同元素类型。

验收标准：

- 生成结果可被 YAML 解析器解析。
- 生成结果符合 Schema。
- 每个场景至少包含 3 个剧本元素。

### 5.6 YAML Schema 校验

优先级：P0

功能说明：

- 系统内置 YAML Schema 或等价 JSON Schema。
- 生成后自动校验。
- 用户编辑 YAML 后可重新校验。

验收标准：

- 校验通过时显示通过状态。
- 校验失败时显示字段路径、错误类型和修复建议。
- 模型输出存在结构、引用或高严重度质量问题时，最多自动修复两轮。

### 5.7 YAML 编辑与导出

优先级：P0

功能说明：

- 支持在编辑器中查看和修改 YAML。
- 支持复制 YAML。
- 支持导出 `.yaml` 文件。

验收标准：

- 导出的 YAML 与页面显示一致。
- 用户编辑后导出的是最新内容。

### 5.8 改编总结

优先级：P1

功能说明：

- 展示本次改编保留了哪些主线。
- 展示合并、删减或改写的情节。
- 给出继续打磨建议。

验收标准：

- 总结不少于 3 条。
- 能关联章节或场景编号。

### 5.9 局部重写

优先级：P1

功能说明：

- 用户选择某个场景后，可重新生成该场景。
- 支持重写风格：更紧凑、更戏剧化、更口语化、更忠于原文。

验收标准：

- 重写只影响选中场景。
- 重写后仍可通过 Schema 校验。

## 6. YAML 输出结构

MVP 输出建议：

```yaml
schema_version: "1.0"
metadata:
  title: "示例剧本"
  source_type: "novel"
  language: "zh-CN"
  adaptation_type: "short_drama"
characters:
  - id: "char_001"
    name: "林夏"
    aliases: ["小夏"]
    role: "protagonist"
    description: "女主角，刚进入职场。"
locations:
  - id: "loc_001"
    name: "会议室"
    description: "公司内部会议室。"
scenes:
  - id: "scene_001"
    source_chapters: ["chapter_001"]
    heading:
      location_id: "loc_001"
      time_of_day: "morning"
    purpose: "建立主角困境"
    conflict: "主角被质疑能力"
    characters: ["char_001"]
    elements:
      - type: "action"
        text: "林夏推开会议室的门。"
      - type: "dialogue"
        character_id: "char_001"
        text: "我会证明这个方案可行。"
adaptation_notes:
  retained:
    - "保留主角进入职场后的核心冲突。"
  changed:
    - "将大段心理描写改为动作和对白。"
```

## 7. 非功能需求

性能：

- 3 章、每章 1500 至 3000 字文本，端到端生成时间目标小于 3 分钟。
- 前端生成进度必须可见，避免用户误以为卡死。

稳定性：

- 用户输入内容在生成失败时不得丢失。
- 模型输出必须经过解析和校验。
- 支持最多两轮局部自动修复，并保存修复前后结果。

安全：

- `.env` 不得提交到 GitHub。
- API Key 通过环境变量读取。
- Demo 样例文本必须使用自写或确认可公开的文本。

可维护性：

- Prompt 模板独立管理。
- Schema 独立文件维护。
- 校验逻辑与模型调用解耦。

## 8. 技术方案建议

推荐架构：

- 前端：React 或 Vue，提供输入、结果预览、编辑和导出。
- 后端：Node.js 或 Python FastAPI。
- AI 层：封装模型 Provider，便于替换不同大模型。
- 校验层：使用 YAML Parser + JSON Schema Validator。
- 存储：SQLite 保存项目元数据和任务状态，本地项目目录保存原文、Agent 中间结果、修复历史和最终 YAML。

推荐处理链路：

1. `parse_chapters(text)`：章节拆分。
2. `extract_story_facts(chapters)`：抽取人物、地点、事件。
3. `plan_scenes(facts)`：规划场景。
4. `generate_script_yaml(scene_plan)`：生成 YAML。
5. `validate_yaml(yaml)`：校验。
6. `repair_yaml(yaml, errors)`：自动修复。

## 9. Prompt 策略

不要直接让模型“一次性把小说转成 YAML”。推荐分阶段：

- 第一阶段：逐章抽取事实，不做改写。
- 第二阶段：合并人物、地点和事件。
- 第三阶段：生成场景大纲。
- 第四阶段：根据大纲生成 YAML。
- 第五阶段：根据校验错误修复 YAML。

每个阶段都要求模型输出结构化 JSON 或 YAML，减少自由发挥。

## 10. 质量评价

系统可计算以下指标：

- Schema 通过率。
- 章节覆盖率：被映射到场景的章节数 / 总章节数。
- 人物一致性：场景中引用的人物 ID 是否存在。
- 场景完整度：是否包含地点、时间、人物、冲突、元素。
- 对白占比：对白元素数量 / 总元素数量。
- 改编说明完整度：是否说明保留、删减、合并、改写。

## 11. 验收标准

必须满足：

- 支持至少 3 个章节小说文本。
- 能自动生成结构化 YAML 剧本。
- 提供并说明 YAML Schema。
- YAML 可解析且可校验。
- 可导出 YAML 文件。
- README 提供运行说明和 Demo 说明。

建议满足：

- 有样例文本和样例输出。
- 有局部重写或自动修复演示。
- 有生成过程进度条。
- 有错误状态处理。
